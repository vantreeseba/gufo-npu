# Qwen3.5-2B experiments

Short retained/rejected decisions; the runs behind them are in
[BENCHMARKS.md](BENCHMARKS.md) and [QUALITY.md](QUALITY.md).

| Experiment | Decision / qualification |
| --- | --- |
| Compact q4nx scales (4736-byte blocks, 4.625 bits per weight) | Retained: 7.5% fewer weight bytes. Sky without drafting 36.9–37.2 → 38.6–39.1 tok/s, Fibonacci with MTP 60.6–61.1 → 63.0–63.7. Rounding d instead of d · sc moves the weights slightly, so greedy replies differ a little. |
| fp16 K/V cache | Retained: halves the cache read per token. 9k context without drafting 28.6–28.7 → 31.6–31.9 tok/s, decoder logits within the 2e-3 tolerance (6.2e-4). |
| 32k draft vocabulary for the MTP head | Retained: the draft's LM head scores 32,768 frequent ids instead of 248,320. 2k prompt then the sky question, with MTP: 41.4–41.7 → 46.5–47.3 tok/s. |
| GEMV residual drain awaited first (DMA wait order) | Fixed: a wait took another task's completion token, about once in 30,000 chained calls (24 mismatching buffers in 200,000 runs → 0). `qwen35_decode_gemv_chain_test` guards it. |
| One chain sequence per layer (out, gate + up, down and the next projection in one instruction stream; RTP words written only when they change) | Retained: same output hashes as main; sky 39.1–39.4 → 40.7–40.8 tok/s without drafting, 53.7–54.0 → 55.3–55.6 with MTP; Fibonacci 38.7–38.9 → 40.1–40.2 and 64.5–64.7 → 66.6–66.7. 0.9 ms less per token (1.1–1.4 expected). Every chain sequence equals the per-call chain bit for bit (`qwen35_decode_gemv_chain_test`). |
| Chained calls' weight fills queued early (each call's fills right after the previous call's, so each column's weight channel streams on across the boundary while the previous outputs drain) | Retained: the same instruction streams for single calls; a layer chain 713–716 → 707–709 µs in a 16-run runlist (1 token), 759–761 → 753–755 (2 tokens); decode sky 40.6–40.9 → 40.9–41.1 tok/s, same replies. Small because the weight FIFOs (depth 2, ~38 KB per column) fill in ~5 µs and then stall. |
| One RTP word per call (k blocks, rounds, stages, residual pieces and tokens packed; unpacked once per call on the core; the core row in a second word written once per sequence) | Retained: 640 → 160 RTP writes per layer chain (~66 ns each). Layer chain 707–709 → 682–684 µs (1 token), 753–755 → 727 (2 tokens); every single call ~10 µs faster (2048 × 2048: 75 → 65 µs). With the early fills, interleaved against 6f1c45d, three runs: sky 40.6–40.9 → 42.2–42.3 tok/s without a draft, 55.6 → 57.2–57.3 with MTP; Fibonacci 40.2–40.3 → 41.6 and 66.7–66.8 → 68.6–68.7; layer submission 973–977 → 942–946 µs; replies the same (`a49f1c4c`, `fdb595fb`); `qwen35_decode_gemv_chain_test` (full length), decode, sampling and prefill tests pass. |
| Deeper weight FIFOs (memtile depth 3, 4 or 8 instead of 2) to hold more of the next call's weights across a boundary | Rejected: does not fit; the memtile runs out of BD IDs (24 per channel) at depth 3 already. |
| Drafting two tokens ahead with the MTP head (the one MTP layer applied twice, fed its own final residual and first draft; verify up to three tokens per pass) | Not built: the gain is there but three tokens do not fit a core. Second-draft acceptance on the NPU decoder (`qwen35_mtp_depth`, greedy, 256 tokens, 2026-11-04): sky a1 64.5%, a2 given a1 58.3%; Fibonacci 92.6% and 87.6%; a lighthouse story 57.3% and 48.6% (the residual through output_norm; shared_head_norm is 0-0.7 points lower). With a step of ~27.2 ms now and ~29.6 ms for depth 2 (a third verified token ~0.7 ms, a second draft's two submissions ~1.7 ms), tokens per step 1.93 → 2.74 on Fibonacci (+31%), 1.65 → 2.02 on sky (+13%), 1.57 → 1.85 on the story (+8%). A core's data memory (64 KB) holds an 8 KB stack, the 36 KB token buffer (2 tokens × 4,096 fp32 slots and the bf16 norm weight), sums, two 4.7 KB weight blocks and the outputs, with ~6.4 KB free; a third token adds 16 KB to the token buffer, and even with no stack only ~51.6 KB of the 53 KB it needs would be free. It needs a token buffer redesign first (the norm weight out of it, or bf16 tokens for the plain and act inputs), which touches every call. |
| Gated DeltaNet decode step on the NPU (conv, delta rule and gated norm as a call in each layer's chain, so a token takes 7 submissions instead of 25) | Rejected for now, by arithmetic (not built): about 2–4% for a second mode in the core program that every GEMV runs. Saved per token, from the 2026-11-04 timings: 18 submission boundaries at 42–60 µs each (a single call takes 67–70 µs from submit to done, against 25–28 µs per call in a runlist; a layer chain takes ~733 µs as a submission, against 666–683 µs in a runlist) and the CPU DeltaNet, ~0.7–0.8 ms of the ~1.0 ms of host time in a 23.8–24.0 ms step. That is 1.5–1.9 ms in all. Spent: the state cannot stay on the array. It is 18 × 1 MiB in fp32 (9.4 MB in bf16), against 2 MB of core memory and ~3.7 MB of free memtile memory, so each layer's call streams its 1 MiB in and out (and a second 1 MiB out for the draft token of an MTP step), together with the α/β rows, conv weights and inputs. That is ~20 µs of in-sequence call overhead plus 26–52 µs of DMA per layer, 0.8–1.3 ms over 18 layers. Net: 0.5–1.0 ms of a 23.7 ms token (2–4%), and about the same per MTP step. A bf16 state would give 4–6%, but its rounding integrates over every token, and the decoder keeps fp32. A separate xclbin cannot share the layers' runlist (one hardware context), so the code would have to join the GEMV core program. That program has 3.8 KB of its 16 KB program memory free on the residual column (12,576 bytes; 11,984 on the others; CI build of 1c9225e), against an estimated ~2.5–3.5 KB for the conv, L2 norms, softplus and exp, the delta rule for 1 and 2 tokens, and the gated norm. If it does not fit, the GEMV loses its unrolling and every call slows (1% of GEMV time is ~0.2 ms). The submission boundaries are the larger half of the gain, and the host's submit-and-wait path is in all 25 of them, so it is the cheaper lever to measure first. |
| Instruction-buffer flow (the 35B's patchable calls) | Rejected for this model: same output hashes, but sky 39.0–39.1 → 38.1–38.3 and Fibonacci 63.1–63.5 → 61.8–62.1 tok/s. The 2B keeps the ELF flow. |
| Prompt processing on bfp16 GEMMs | Retained: time to first token 0.11 s at 35 tokens and 1.23 s at 4k (the decode path took 33 s at 2,120 tokens), for ~1.56 GB more pinned memory. Logits 1.0–3.3e-2 from the decode path; first generated token always matches. |
| First token from the prefill's last row (LM head alone) | Retained: no decode step for the last prompt token. TTFT 0.107 → 0.086 s at 35 tokens, 0.317 → 0.291 s at 1k, 1.235 → 1.195 s at 4k (with the AVX-512 row below). First token the same on all 10 test prompts (largest logit change 0.89; it may differ only at a top-2 gap under 2 logits). The Fibonacci MTP reply changes at a late near tie (`69e1c62d` → `fdb595fb`) and still equals plain greedy. |
| AVX-512 delta rule in the prefill DeltaNet | Retained: bit-identical, DeltaNet at 4k 0.258 → 0.246 s, ~1% of TTFT (the research's −0.1 s assumed instruction-bound jobs). |
| Short-prompt crossover after the change | Unchanged at 7 tokens: 6 tokens 0.076 s on the decode path against 0.082 s through prefill, 7 tokens 0.097 against 0.082. |
| Search fit for requantized weights (`q4nx::Fit::kSearch`, which the 35B and 4B use) | Rejected for this model; it keeps `kMinMax` (`qwen35::Q4nxFit`). Mixed on the 2B: on 1,515 held-out positions KL against the GGUF falls 22–23%, top-1 rises 0.33 points without the LM head but falls 0.40 points (6 positions) with every matrix in q4nx, the decode set. NPU decode vs CPU 73/73, vs HF 61/73 (63/73 before); hashes change, speed unchanged (sky 38.9–39.3, Fibonacci MTP 62.7–62.8 tok/s); load 2.6 s instead of 1.3 s. A clear win on every measure was the bar, and the decode set's top-1 is not. Importance weighting (below in the 35B's EXPERIMENTS.md) is the next candidate for this model too. | See [the 35B's measurements](../qwen3.6-35b-a3b/QUALITY.md#choosing-the-4-bit-values). |
