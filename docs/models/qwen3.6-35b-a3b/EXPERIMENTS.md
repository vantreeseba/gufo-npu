# Qwen3.6-35B-A3B experiments

Short retained/rejected decisions; the runs behind them are in
[BENCHMARKS.md](BENCHMARKS.md), [QUALITY.md](QUALITY.md) and
[the MoE spike](../../research/NPU-MOE.md).

| Experiment | Decision / qualification |
| --- | --- |
| Expert selection by gathers with patched DDR offsets | Retained: two calls per layer (gate + up over 9 experts, then down with K = 9 × 512), their offsets and router scales rewritten in the instruction stream after CPU routing: 414 µs per layer in a 40-layer chain, against 948 µs for one run per expert matrix. |
| Every matrix in q4nx, LM head included | Retained: the same 4.625-bit class as FastFlowLM's pack (which keeps only its LM head at 8 bits). Top-1 against the GGUF 88.0% (non-expert matrices alone 92.0%); the NPU path matches the CPU over the same weights (263/301 against llama.cpp, CPU 260/301). Decode 19.8–20.3 tok/s against FLM's 16.9–17.1. |
| Non-expert matrices at 8 bits on the NPU | Not built: 2.75 GB per token as stored puts the NPU's ~56 GB/s ceiling near 15–18 tok/s, about FLM's speed. |
| CPU and NPU splitting each matrix by rows | Not pursued: together they read ~170 GB/s against ~120 for the CPU alone, but each split point costs a sync; the NPU-only path was chosen. |
| Instruction-buffer flow for the 2B too | Rejected: it costs Qwen3.5-2B ~2% decode (39.1 → 38.2 tok/s, same output); only MoE models, whose gathers need patched instruction streams, use it. |
| MTP speculation with two-token passes over the expert union | Retained: a pair reads the dense weights once and the union of both tokens' experts (8 to 16 routed plus the shared one) once; each token weighs the other's experts 0 and experts sum in id order, so a two-token pass is bit-identical to two one-token passes and speculative output equals plain greedy. 26.0–28.9 tok/s at short and ~1k context with 75–83% of drafts kept, against 18.7–20.3 without and FLM's 16.9–17.1. The prompt runs two tokens per pass: 942 tokens in 31 s instead of 48 s. |
| Padding every pair's union to 17 experts (one gather variant) | Rejected: each expert costs ~37 µs per layer (480 µs at 9, 779 µs at 17), 4.5–7.6 ms per step at typical unions of 12–14; a variant per count (9 to 17) costs only instruction streams. |
| Down gather over 17 experts: `MAX_DIM` 8,704 or two calls | `MAX_DIM` raised from 6,144 to 8,704: no runtime cost (Qwen3.5-2B same outputs and speed); two calls would need an accumulating output stage and a further call per layer. |
| Error-minimizing fit for requantized weights (llama.cpp's Q4_K search, weights av + &#124;w&#124;) | Retained for this model (`qwen35::Q4nxFit` names `q4nx::Fit::kSearch` for its decoder, MTP block and draft head; the NPU prefill converts those buffers): on 1,515 held-out positions KL against the GGUF falls 24–27% on every weight set (all matrices: 0.0394 → 0.0301, top-1 91.95% → 93.07%; oracle top-1 against llama.cpp 260 → 271 of 301). Same format, kernel and decode speed; packing 1.4 ns per weight on 32 threads (0.4 for min/max). See [QUALITY.md](QUALITY.md#choosing-the-4-bit-values). On the NPU (2026-10-28): `qwen36_npu_decode_test` top-1 against llama.cpp 271/301 instead of 263/301, NPU against the CPU over the same weights 301/301, MTP 77% of drafts kept; `qwen36_npu_prefill_test` passes, argmax after prefill against decode 167/170 (170/170 with min/max; threshold 95%; the first token after prefill is the same on 10 of 10 prompts); decode 19.4–20.4 tok/s on sky without a draft and 29.3–29.8 on Fibonacci with MTP, new hashes `c4d7f8e2` and `9430fd17`. |
| Equal weights in the fit; refitting d and dmin | Rejected: 6% and 0% of the gain. |
| Importance (imatrix) weighting from activation statistics | Next step, measured, not built: KL halves again (non-expert set 0.0230 → 0.0111). Unsloth's published `imatrix_unsloth.gguf` gives the same as our own calibration pass (0.0107), so the NPU loader can read it instead of calibrating. |
| AWQ input scaling (powers of two, absorbable on the NPU path) | Rejected: helps only without the importance weighting (0.0261 → 0.0194), nothing on top of it (0.0149 → 0.0153). |
| Skipping the LM head on decode-path prompt passes | Retained: only the last pass's logits are read, so the others stop after the last layer's down gather and take the final residual from the LM head's input region (H + D, the same fp32 sum its input stage writes). 942-token prompt on the decode path, interleaved against main, two rounds: 31.0 → 28.4 s (−8.4%), same first token. |
| NPU prefill v1: layer by layer over the whole prompt, the decoder's q4nx converted on the NPU per layer | Retained (docs/research/NPU-MOE-PREFILL.md): per layer the GEMM program runs the input projection, the CPU mixer and the output projection in blocks of 1,024 tokens; the CPU routes; one visit to the dequant program converts the experts with tokens and the next layer's dense matrices; the GEMM program runs every expert's gate + up and down. Two program switches per layer (80 per pass), nothing kept beside the decoder's weights but ~1.25 GB of scratch. TTFT 3.32 s at 125 tokens, 5.56 s at 1,055, 9.77 s at 4,246 and 16.0 s at 8,499, against FLM's 5.17, 8.75, 19.5 and 34.2 s; prompts under 108 tokens stay on the decode path, which is faster there. The expert step sits behind `ExpertStep` (expert_step.hpp), so a CPU expert step can replace it. |
| Dequant rounding each weight once | Retained: the spike's kernel rounded each weight to bf16 and then to bfp16, and d·sc to bf16 (weights vs q4nx 8.4e-3, GEMM output 1.08e-2). Building dmin·mn + d·sc·code in fp32 (d·sc and dmin·mn as exact bf16 hi + lo pairs, the operands transposed before the MACs) gives 6.170e-3 against 6.163e-3 for the host's packing, and every prefill GEMM 9.1–9.4e-3 against the CPU (limit 1e-2). |
| Reusing XRT runs across batches (call setup) | Rejected: at 1,024 tokens 5.41–5.45 s against 5.17–5.19 s making a run per call; on the ELF flow setting a buffer argument re-patches the run's own instruction stream, so a reused run saves nothing and costs more. |
| Keeping the calls' buffer windows (sub-buffers) for reuse | Rejected: 5.29 s against 5.13 s at 1,024 tokens (3.14 against 3.07 s at 125), interleaved, two rounds. |
| The prefill programs on the instruction-buffer flow | Rejected: building the calls drops from ~0.5 s to 0.18 s at 1,024 tokens, but each call costs more on the NPU (dequant 1.56 → 1.93 s, GEMMs 1.84 → 1.96 s): 5.25 s against 5.13 s. |
| Passes of up to 16,384 tokens (not 8,192) | Retained: each pass converts every expert again, so FLM's 8,499-token prompt runs as one pass (16.0 s); the group buffers grow by ~60 MB. |
